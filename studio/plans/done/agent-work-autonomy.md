# 工作列表、Agent 自主执行与中台身份

状态：做完（源码、隔离验证与本机归档；编译和加载等用户安排）。

## 用户决定（2026-11-13）

公司导航在工作群、Agent 管理、组织架构下增加工作列表。工作有低、中、高优先级，可分配给具体 Agent；每个 Agent 可以选择模型。Agent 自主执行已分配的工作、互相聊天交接并汇报结果。当前开发助手定位为“中台工具Agent”，当前聊天完整收集为它的本机资料。继续只改源码、隔离验证和推送自己的 GitHub，不编译、不刷新、不重启，不打断已有工作。

## 做法与原因

- 工作、Agent 身份和项目任务分开存储，工作引用负责 Agent 及汇报群。列表提供过滤、验收条件、最近汇报、编辑未派发工作、启动、核查重试、取消和打开工作会话。
- 调度以优先级和创建时间排序，每个 Agent 一次处理一项工作；自主接活关闭时等人启动。未配置的 Agent 保留队列，忙碌会话等本轮真正结束。没有新分配目标时不轮询模型，不自行创造工作。
- 使用现有公司消息与会话收件箱派发，保存幂等键、消息关联和尝试次数。回执缺失或恢复时有歧义的请求显示受阻，不自动重放；重试需要核查未知结果。任务失败和回合结束但未确认验收也回群汇报，不自动判成功。
- 会话绑定决定工具身份。`company_work_read` 只读自己的工作；`company_work_report` 原子写工作状态和群汇报，支持完成、受阻、进度、转交；工作交接最多四次。普通 Agent 互聊继续使用已有群工具的成员、回复链与转交上限校验。
- 使用实际渠道的模型列表，保存到 Agent 资料，新公司任务进入空闲回合前校验并应用，保留会话已有权限。模型准备期间人开始工作时不插入任务。
- 自我进化采用可撤回的工作规范迭代。只能引用自己已完成的工作，有依据、前后版本和乐观锁；不改身份、权限或别人的 Agent，不训练底层模型。人工修改与撤回同样记为新版本。
- 默认新增中台工具Agent并加入公司协作群；已有自定义成员不重置。当前开发会话和完整本机快照通过忽略的 company-bootstrap 文件关联；原生来源不恢复为执行会话，原文、附件与本机路径不进 Git 或自动外发。

## 验证边界

只做 TypeScript noEmit、临时 SQLite / 模拟运行时测试和独立静态界面截图；不编译应用，不向真实模型发测试任务，不读取或改写运行库中的任务状态。编译加载及真实多 Agent 验收由用户另行安排。
