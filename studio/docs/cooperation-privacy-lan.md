# 合作模式、隐私与局域网手机连接

本 fork 用户在 2026-11-10 确定隐私规则，2026-11-11 调整为团队远程、Work中转与手机远程独立。顶栏“合作模式”集中管理；书签关闭但历史数据保留。“收起窗口”仅收起界面。

## 开关和账号

- “关闭远程”：仅停止当前团队账号的设备通道（用户目前的团队服务为 172.16.8.85:47120），配对与授权记录保留，重启保持关闭；不影响手机远程。
- “关闭中转”：停止 Host 中转轮询与客户端连接；独立于远程。接收中转聊天不等于授权远程访问任务。
- “一键关闭合作模式并退出账号”：先断开远程/中转，再退出共享账号并停止本机手机服务。已经提交给 Jenkins 的构建不取消；本机正在执行的模型任务也不会被终止。
- 团队账号复用 `%APPDATA%/AMO/account.json`，凭据按 Windows 用户加密。WorkStudio 与平台共用团队账号，退出会影响平台登录，但不退出手机账号、不关闭手机服务。
- 手机账号、密码散列、登录令牌散列位于独立的 `phone-server/relay.db`，设备授权元数据按手机账号命名空间隔离。手机连接不读取或写入平台账号文件；同名团队账号也不是同一个账号。
- 手机服务不开放远程注册和管理接口，账号只能通过本机 Host 的认证设置接口管理。重设密码、停用和删除会撤销令牌并断开已有连接；删除账号不删除电脑的任务与会话。原有本机服务账号保留，但需在账号管理中明确启用。
- “关闭手机远程”停止监听和所有手机连接，不影响团队账号与团队远程；账号保留，重启保持开关状态。手机服务默认关闭，允许局域网另行选择。

## 手机连接步骤

1. 电脑打开“合作模式 → 手机远程”，创建手机账号（12–128 位密码）。此账号具有完整本机 WorkStudio 聊天的查看与接管权限，只给信任的人使用。团队账号不用退出。
2. 开启手机远程并勾选“允许同一局域网的手机连接”。未允许 LAN 时只监听 `127.0.0.1:47950`。
3. 手机安装新版 WorkStudio APK，填写电脑显示的局域网地址（例如 `http://192.168.1.10:47950`），使用电脑刚创建的手机账号登录。手机不要填写自己的 `127.0.0.1`。
4. 从手机的在线设备里选择名称带“手机远程”的电脑申请配对。本机已明确创建并启用的同账号手机可自动配对，其他手机账号之间不配对。连接后只同步本机未归档聊天及新聊天；归档任务、归档分支、原生导入历史与其他电脑的远程副本不转授权。点击聊天直接进入正文和输入框，分支列表从聊天菜单打开。
5. 手机可收发消息、接管当前聊天、选择全部可用模型、低/中/高等实际支持的思考强度、Fast、权限、审批、提问和 # 提示词。跨渠道接续仍保留原记录；执行始终在电脑，结果流式同步到手机。
6. 需要团队消息时，保持团队账号登录并另行开启 Work中转。在手机账号行勾选“同步团队来信”，来信建立本地聊天并只同步给勾选的账号，附带原文但不会自动执行。手机回复后才由本地所选模型处理。关闭此项立即收回这些来信聊天的后续读取权限；新版手机收到撤销或下次刷新后清理缓存，无法收回用户另行截图、复制的内容。

合作弹窗支持滚轮和拖动滚动条，“管理手机账号”按钮直接滚动到账号表单。弹窗移到 Electron 标题栏拖动区域之外，并只保留一个滚动容器，避免滚动条操作被当成拖动窗口。

手机服务显示的多个 HTTP 地址来自电脑的不同网卡，指向同一个服务。手机只需把其中一个可达地址填入 App 的“服务器地址”，不用在浏览器逐个打开；优先使用电脑实际接入局域网的网卡地址。虚拟网卡地址通常不可达，`169.254.*` 自动分配地址放在折叠说明里，通常不选。

同一可达局域网不需要 Tailscale。Wi-Fi 的访客隔离、公司网络 ACL 或 Windows 防火墙可能阻止 47950；本次没有修改公司网络或自动添加防火墙放行。5G 不能直接连公司内网地址。无公网服务器时可在手机和电脑安装 Tailscale，加入同一 tailnet，手机填电脑 `http://100.x.x.x:47950`；电脑开启手机服务和 LAN 监听，使用独立手机账号，团队远程可以保持关闭。网络连通和端口策略仍须允许，未验证实际 5G 链路。参见 [Tailscale 设备连接](https://tailscale.com/docs/how-to/connect-to-devices)。

本机服务复用 Relay 的登录/设备协议，但账号和授权是独立域，不连接团队服务器。数据在 Studio 数据目录旁的 `phone-server/`；原 `.data` 与已有中转数据均保留。Android 工程在 `mobile/`，应用名 WorkStudio，图标为原创二次元女性头像；APK 是内部调试签名。iOS 共用代码、名称与图标已同步，IPA 未在 Windows 编译/签名。检查范围与验证结果见 [手机与原生历史隐私检查](mobile-privacy-audit.md)。

## 隐私边界

已关闭原生 Claude 会话列表、预览、接续导入，删除 runtime 的原生历史导入实现；Codex 只使用 Studio 数据库已有的会话引用，不新增原生历史导入。带有旧 `claude-adopted:*` 导入标记的任务不能远程授权或走 AI 中转。工作台自己的会话、分支及子代理日志仍会被读取，以恢复其任务；模型登录/额度功能也仍使用用户配置的模型凭据，这与导入原生历史不同。

Host 远程文件读取及 Review 内容外发需要电脑弹窗批准；分块仅在同一文件/接收方短期批准内继续，撤回授权或关闭远程后再检查。已知原生客户端私有目录禁止发送，解析符号链接后检查。中转 AI 发问/追问固定等待人点发送；集成中转窗口手动上传也有原生确认框。模型的自动审批/全部允许不关闭这些应用内规则。

未发现新增全局键盘记录或剪贴板读取监听；用户主动粘贴仍属于输入动作。剪贴板复制功能仍保留。旧独立中转程序与外部 CLI 配置已移到可恢复的停用备份目录，用户数据未删除；没有改写 `.codex` 或 `.claude` 的历史/配置。

这不是操作系统隔离。获不受限 shell 权限的模型或用户自行配置的 MCP 仍可能读取任意可访问文件或联网；应用层路径检查不能识别人为复制、改名或粘贴的原生对话。若要“即使全部允许也绝对不能外发”，还需要独立 Windows 用户/沙箱与网络策略。不能把本次检查描述为零漏洞或绝不泄露的证明。

远程/中转协议目前信任所选服务器，并非端到端加密；服务器可见经过它的聊天/附件。LAN 的 HTTP 流量没有 TLS 加密，应仅连接可信服务与可信局域网。收回授权不会抹除对方此前已经同步的数据。
