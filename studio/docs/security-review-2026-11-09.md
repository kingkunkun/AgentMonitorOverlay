## 检查结果和重要边界

- npm audit：0 个已知漏洞（2026-11-09 查询）；不等于没有未知漏洞。
- 未发现产品代码主动读取剪贴板、记录键盘、录屏或新增通用遥测 SDK。复制功能写剪贴板；查看器提供的 readText 明确拒绝。未发现新增整机 Codex/Claude 聊天记录批量上传逻辑。
- 会读取本地数据：自己的 SQLite/会话/附件、平台登录、设备 ID/名称、模型登录/配置，以及 Studio 管理的模型运行日志。新版读取 Codex 配置以关闭依赖 Codex 桌面宿主的工具；DSH 子会话跟踪读取 DSH 的会话日志。这些是功能数据读取，不能称为“完全不收集/不读取客户端数据”。
- Claude“接续已有会话”会在用户使用入口时列举/预览本地外部会话，选择后复制并导入；源码路径 runtime/claude/outside.ts，本次上游仅移动文档引用。Studio 管理的会话也会读取自身日志以恢复状态、统计用量。未发现把所有外部聊天记录自动交给团队服务器的新增逻辑。
- 模型收到提示词、上下文和使用过程中读取的文件内容，属于正常模型请求；自定义模型站点也会收到这些内容。模型/CLI/MCP 扩展自身的行为不在本次源码静态检查的保证范围内。
- 远程任务授权是按任务：grants.ts 的 snapshot 包含该任务的会话列表，items 按会话同步聊天条目。因此授权者应把任务里已有聊天及后续回复视为对端可见，并会在对端留下缓存。收回授权阻止后续操作，不会远程擦掉已同步记录。
- 远程文件读取先 realpath 再校验范围，限制在任务项目目录和会话附件；此处“任务目录”通常是整个项目目录。没有通用敏感文件名过滤：项目里的 .env、日志、密钥文本不能假设会被自动遮挡。新版增加 HTML 的 CSS、JS、字体加载，字体另做格式校验。
- 远程开启并授权后，对端能发消息、审批、打断和开会话；AI 命令仍在原电脑以本机用户和模型账号运行。UI 的文件浏览限制并非 AI 命令的操作系统沙箱。不能据此保证“只能发任务、绝不能操作本机文件”。
- 新版远程额度共享：同账号设备可看相关缓存额度；其他账号须另勾选共享。不会为远端额外查询模型站点（features/remote/usage.ts）。
- **行为变化：关闭远程不等于关闭全部团队通信。** remote.setEnabled(false) 持久关闭远程链路，但 host-process.ts 现在独立启动 TeamLink 和 TeamRelay；teamrelay/service.ts 登录后仍轮询中转，能将此前中转问询的回复转入原 AI 会话。它与此前“关闭远程后不联系服务器、不接收消息”的严格要求有差距。本次记录该差距，未把上游的独立中转改造成全局断网开关。
- 中转发送默认等本机用户确认；设置 teamAutoSend=true 时 AI 可直接发正文和指定附件（teamrelay/service.ts）。团队服务器会接收/保存中转内容；设备远程转发也经过该服务器。源码未提供可据以宣称端到端保密的保证。HTTP/WS 是明文传输，需 HTTPS/WSS 或可信的加密网络覆盖。
- 桌面 HTML 查看器允许脚本，使用 sandbox 隔离来源；没有据此证明页面不能联网。只预览可信 HTML；本次未做恶意页面动态渗透测试。

若目标是避免团队消息进入 AI，单独关闭远程不足；应退出平台团队账号（同时影响其他工具），或另实现全局团队通信开关。若希望 AI 不能修改本机文件，应使用 CLI 的只读/沙箱权限或独立受限系统账号；远程配对不是该隔离层。

## 手机端流程

Android 是远程客户端，源码 mobile/，通过 mobile/build.ps1 构建（JDK 17、Android SDK 36）；本次没有构建或安装手机包。iOS KMP 工程已存在，但仓库 plans/ios.md 仍记录等待发布凭据和真机验证，不能视为已经公开可安装的正式版。

电脑在平台登录 → 打开 Studio 远程 → 手机连同一 Relay 服务器并登录 → 手机申请配对 → 电脑确认 → 电脑授权已有任务，或勾选远端允许项目和模型 → 手机查看任务/聊天、发消息、处理审批/提问、停止任务、查看回复文件。模型和命令始终在电脑执行；手机退到后台不会停止电脑任务，电脑需要保持运行。手机会缓存已同步的会话。

## @账号、中转和接手的区别

1. AI 用 team_members 找人，team_ask 指定接收账号、标题、正文、问题和附件；默认在 Studio 中等待本人确认。接收方在 AMO 中转看到这一条中转会话，回复后回到发起的 AI；team_followup 可追问，team_done 收尾。
2. 中转发送的数据是明确的正文、问题、附带文件及该中转会话后续消息，并不会因为 @ 某个账号自动上传原 Studio 的全部聊天。AI 自己把上下文写进正文、或者附上敏感文件时，这些内容就会被发送。
3. “已接手，不用回复”表示收件人承担后续工作，把中转会话标结束；默认不会让发起 AI 再跑一轮。勾选“把附言转给发起的 AI”时附言会转回并可能触发运行。这个按钮不授予远程电脑控制权。
4. “我来处理/交还给 AI”是发起人切换谁处理这条中转会话；“接手任务”是团队任务的负责人流转，也不等于获得源电脑的操作权限。
5. 真正接着操作源电脑上的 AI 会话，需要另走远程配对、任务授权。授权后才能看该任务会话记录和继续发话/审批；模型仍用源电脑账号并在源电脑执行。

## 工具功能总览

| 模块 | 作用 |
|---|---|
| WorkStudio | 项目/专题/任务看板；Codex、Claude、DeepSeek 会话；子会话、分支、计划审批、提问、停止、用量；画布/主控协作；书签、待办、进度、Focus 提醒 |
| Reviewer | Git 变更审阅，文本/Markdown/HTML/图片查看与批注，批注返回会话；新版本含 HTML 查找和图片放大 |
| AMO 便签 | 随手记、托盘、快捷键，独立可用 |
| AMO 中转 | 人际聊天、AI 找人确认、问题/附件/批注、回复回流、团队任务和负责人流转 |
| 远程 | 配对/解绑、允许项目和模型、新任务确认策略、按任务授权/收回、跨设备发消息/审批/查看文件、额度展示 |
| AMO 平台 | 团队账号登录、工具安装/版本更新/启动和环境管理 |
| Relay 服务 | 团队账号、聊天/附件存储和设备转发；部署和管理由服务器负责人控制 |
| 手机端 | 经 Relay 操作电脑上的授权任务；不是把本机 AI 搬到手机执行 |
